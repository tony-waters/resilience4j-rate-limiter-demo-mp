# Order creation never fails on notification outcome

Placing an Order synchronously calls `email-service`, which may succeed, be rate limited (configured to fail fast — `timeoutDuration=0`, no queuing for a free slot), or fail outright. `POST /orders` always returns `201 Created` with the Order's Notification Outcome (`Sent`/`RateLimited`/`Failed`) embedded in the response and persisted on the Order row; the notification result never causes order creation itself to fail. Order placement is the primary business event and shouldn't be coupled to the availability of a secondary side-channel — this also lets tests assert on the outcome directly instead of tailing logs.
